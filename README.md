# DeX Tablet 0.2.0

DeX를 지원하는 갤럭시의 화면을 USB로 안드로이드 태블릿에 받아 표시하고, 태블릿의 키보드·마우스 입력을 휴대폰으로 보내는 앱입니다. **수신 태블릿의 제조사나 모델을 제한하지 않습니다.** Android 9 이상, USB 호스트/OTG, 지원되는 H.264 디코더가 필요합니다. 휴대폰 쪽은 Samsung DeX 지원 갤럭시와 호환 펌웨어가 필요합니다.

**현재 상태: APK 빌드 및 34개 합성 테스트 그룹 통과. 실제 태블릿/갤럭시 조합의 화면·입력·DeX 호환성 검증은 아직 수행하지 않은 개발 빌드입니다.** 범용 설치 대상이라는 설명은 모든 태블릿에서의 동작 보증을 뜻하지 않습니다. 가상화면이 생성된다는 것과 Samsung DeX의 모든 창 기능이 정상 동작한다는 것도 다릅니다.

**[태블릿용 APK 다운로드](https://github.com/ssfssd/dex-tablet/releases/download/v0.2.0/DeXTablet-0.2.0-debug.apk)** · [릴리스 페이지](https://github.com/ssfssd/dex-tablet/releases/tag/v0.2.0) · [SHA-256](https://github.com/ssfssd/dex-tablet/releases/download/v0.2.0/DeXTablet-0.2.0-debug.apk.sha256)

태블릿 브라우저에서 APK를 내려받아 열면 설치할 수 있습니다. Git이나 Android Studio는 필요하지 않습니다. GitHub의 `Source code` 파일은 설치 파일이 아닙니다.

## 설치 및 연결

1. 위의 **태블릿용 APK 다운로드** 링크에서 `DeXTablet-0.2.0-debug.apk`를 받아 **화면을 표시할 태블릿에** 설치합니다. 로컬 빌드 파일은 `dist/`에 있습니다. 갤럭시에 scrcpy 앱을 따로 설치할 필요는 없습니다. Windows PC 설정은 변경하지 않습니다.
2. 갤럭시에서 개발자 옵션의 **USB 디버깅**을 켭니다. 개발자 옵션이 없으면 `설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호`를 여러 번 누릅니다.
3. 데이터 전송을 지원하는 USB 케이블로 연결합니다. 수신 태블릿이 **USB 호스트/제어 주체**가 되어야 합니다. USB 환경설정에서 역할을 바꿀 수 없다면 태블릿 쪽 OTG 어댑터 또는 호스트용 USB 허브와 데이터 케이블을 사용합니다. 충전 전용 케이블은 사용할 수 없습니다.
4. 태블릿에서 **DeX Tablet → USB 기기 다시 찾기 → 유선 DeX 시작**을 누릅니다. 태블릿의 USB 접근 요청과 **갤럭시 화면의 USB 디버깅 허용 요청**을 각각 허용합니다. 갤럭시 잠금을 해제한 상태에서 시작합니다.
5. 처음에는 `자동 · 화면 비율/디코더에 맞춤`, `가상화면`, `물리 키보드 전달`을 선택합니다. 앱은 실제 표시 영역 비율로 해상도를 정하고 디코더가 알리는 지원 범위에 맞춰 최대 프레임률/해상도를 낮춥니다. 실제 처리 속도까지 보장하는 것은 아니므로 끊기면 `가볍게`를 선택합니다.
6. 한글 입력은 상단 **키보드 설정**에서 갤럭시에 생성된 물리 키보드의 언어/배열을 한국어·영어로 설정한 뒤 **한/영** 또는 Shift+Space 등 해당 입력기의 전환 키를 사용합니다. 기본 입력기로 Samsung Keyboard를 사용하는 경우도 실제 설정을 확인해야 합니다.
7. **연결 종료**를 누르고 종료 처리가 끝난 뒤 케이블을 분리합니다. **Ctrl+Alt+Esc**는 앱이 해당 키를 수신할 때 종료 메뉴를 여는 단축키입니다.

앱 설치 출처 허용이 필요한 경우 Android가 표시하는 해당 설치 앱의 안내를 따릅니다. 루팅, 기기 관리자 권한, 접근성 서비스, 인터넷 권한은 요구하지 않습니다.

## 구현 범위

| 기능 | 구현 방식 및 범위 |
|---|---|
| 유선 화면 | Android USB Host로 ADB 연결, scrcpy 4.1 서버, H.264 하드웨어 디코딩 |
| 가상화면 | 휴대폰에서 별도 화면을 생성하고 해당 화면의 freeform 창 모드를 설정. 지원 펌웨어에 종속 |
| 보조화면 호환 모드 | 휴대폰의 개발자 보조화면을 생성해 표시. 기존 값 기록 및 종료/동일 기기 재연결 시 복원 시도 |
| 전용 키보드·USB 키보드 | 태블릿이 Android 키 입력으로 인식한 이벤트를 USB HID 키보드 보고서로 전달. 호환되지 않으면 물리 키보드 체크를 해제해 기본 키 이벤트로 재연결 |
| 태블릿별 화면 구성 | 16:10, 4:3, 3:2, 세로 등 현재 표시 영역 비율 반영. 지원 디코더 이름/크기/프레임률 확인 후 선택. USB 호스트 또는 H.264 디코더 미지원 시 시작 전 안내 |
| 터치·마우스·터치패드 | 한 손가락 터치, 클릭/드래그, 포인터 이동, 우클릭, 휠. 복잡한 여러 손가락 제스처는 미구현 |
| 소리 출력 | 갤럭시 캡처 오디오를 태블릿의 기본 오디오 출력으로 재생. 앱별 캡처 정책에 따라 제외될 수 있음 |
| USB 저장장치 | 태블릿 파일 선택기에 나타나는 파일을 선택하여 갤럭시로 전송. 반대로 갤럭시 공유 저장소 파일을 태블릿/USB 저장장치에 저장 |
| 붙여넣기 | 사용자가 버튼을 누른 경우에만 태블릿 클립보드 텍스트 전달 |
| 진단 | 연결 화면의 **연결 진단 복사**. 앱 메모리의 서버 로그와 실행 모드만 수동 복사. 자동 업로드 없음 |

USB 장치 자체의 전달은 구현하지 않았습니다. **태블릿 포트에 연결한 웹캠·마이크·랜카드·프린터·HDMI 장치 등이 갤럭시의 장치로 자동 인식되는 기능은 없습니다.** 파일 전달과 키 입력 전달은 USB 포트 전체 공유와 다릅니다. 태블릿에 연결한 헤드폰/DAC에서 소리가 나는지는 태블릿의 Android 오디오 출력 설정에 따릅니다.

## DeX 모드의 차이

- **가상화면:** scrcpy의 `new_display`로 생성합니다. One UI 8.5/9 계열에서 새 화면에 `wm set-display-windowing-mode -d <생성한 ID> 5`를 적용하는 방식을 사용합니다. 펌웨어가 이 명령을 지원하지 않으면 경고합니다. 창 장식이 기존 Samsung DeX와 다를 수 있으며, 분할 화면·작업표시줄 등 전체 DeX 기능을 보장하지 않습니다.
- **보조화면:** 개발자 옵션의 `overlay_display_devices`를 이용합니다. Samsung이 외부 화면으로 취급하는 경로이지만, 휴대폰에 보조화면 창이 보이고 일부 One UI 9 환경에서는 창 제목줄 드래그가 SystemUI 재시작을 일으킨다는 upstream 보고가 있습니다. 사용자 선택 후 설명을 확인해야 실행됩니다. 가상화면으로 먼저 시험하세요.
- 둘 다 태블릿의 USB-C 영상 입력 기능을 사용하지 않습니다. 영상이 USB 데이터로 들어오므로 DP 입력 지원 여부와 별개입니다.

다른 보조화면 설정이 이미 있으면 보조화면 모드 실행을 거절합니다. 복원은 **동일 휴대폰의 현재 값이 앱이 만든 값과 일치할 때만** 수행합니다. 사용자가 다른 값으로 바꿨으면 덮어쓰지 않습니다. 강제 종료·케이블 분리 뒤 같은 휴대폰으로 다시 연결하면 남은 복원을 먼저 시도합니다. 앱을 삭제하면 앱 내부 복원 기록도 사라집니다. 남은 보조화면은 휴대폰의 `개발자 옵션 → 보조 디스플레이 시뮬레이션 → 없음`에서 해제할 수 있습니다.

## 파일 전달

- **파일 보내기:** 태블릿 시스템 파일 선택기에서 파일 하나를 선택합니다. 휴대폰의 `Download/DeXTablet/<무작위 ID>_<원래 파일명>`에 저장하여 기존 이름과 충돌할 가능성을 줄입니다.
- **파일 받기:** 휴대폰의 `Download`부터 공유 저장소 폴더를 탐색한 다음, 태블릿 시스템 파일 선택기에서 저장 위치를 선택합니다. 앱 전용 데이터나 보호된 파일에 접근하는 기능은 없습니다.
- 한 번에 하나의 파일 전송을 실행합니다. 실패한 태블릿 출력 파일과 연결이 살아 있는 동안의 실패한 휴대폰 출력 파일은 삭제를 시도합니다. 케이블이 끊기면 휴대폰에 부분 파일이 남을 수 있습니다.
- 파일 선택기 표시 중 입력을 해제하고 영상 렌더링을 일시 중지합니다. 돌아오면 새 영상 프레임을 요청합니다. 제조사별 실제 문서 선택기 및 USB 저장장치 조합은 실기기 확인 항목입니다.

## 알려진 제한과 확인 사항

- USB 역할 협상, Samsung 보안 정책의 USB 디버깅 허용 여부, One UI 빌드별 창 관리가 실제 연결 가능성을 결정합니다. 앱으로 USB 호스트 역할이나 보안 차단을 강제로 바꾸지 않습니다.
- 태블릿 OS가 먼저 처리하는 홈/최근 앱/일부 시스템 단축키는 전달되지 않을 수 있습니다. 상단의 **뒤로/홈/최근 앱** 버튼으로 휴대폰에 명시적으로 보낼 수 있습니다.
- 화면 잠금, DRM 및 앱 자체의 캡처 제한으로 영상/소리가 제외될 수 있습니다. 마이크 입력 전송은 지원하지 않습니다.
- 일반적인 앱 백그라운드 전환과 화면 소멸 시 세션을 종료합니다. 시스템 파일 선택기를 여는 동안은 연결 유지를 시도합니다. 상시 백그라운드 서비스나 자동 연결은 없습니다.
- 주사율, 지연 시간, 배터리/충전 방향, 키보드 배열, 제조사별 회전/멀티윈도우, 블루투스 또는 USB 오디오 출력은 측정하지 않았습니다. 수신 태블릿 브랜드를 검사하지 않으며 Lenovo, Samsung, Xiaomi 등 특정 브랜드의 실기기 검증 완료를 주장하지 않습니다.
- 오류가 나면 연결 화면의 **연결 진단 복사**를 사용합니다. 디버깅 허용 화면을 확인하지 못한 경우에는 갤럭시 잠금과 케이블/USB 제어 주체부터 확인합니다.

## 빌드 및 테스트

실제 빌드는 Gradle 다운로드 없이 이미 설치된 Android SDK와 JDK로 수행했습니다.

```powershell
.\scripts\test.ps1
.\scripts\build.ps1
```

필요 도구: JDK 17, Android SDK Platform 35, Build Tools 35.0.0. `-Java`와 `-Sdk`로 설치 경로를 지정할 수 있습니다. 빌드는 APK 서명과 정렬을 확인하며 `dist/*.sha256`도 생성합니다. 개발용 서명 키는 `build/signing/debug.jks`에만 저장되며 배포 소스 묶음에 포함하지 않습니다. 이 파일을 보존해야 이후 개발 APK를 같은 서명으로 업데이트할 수 있습니다.

`settings.gradle`, `build.gradle`, `app/build.gradle`은 Android Studio 프로젝트 열기용입니다. Gradle 경로는 이 환경에서 실행하지 않았고 wrapper는 포함하지 않습니다.

검증 기록과 실기기 수락 항목은 [VALIDATION.md](VALIDATION.md), 프로토콜 및 의존성 출처는 [SOURCES.md](SOURCES.md)에 있습니다.

## GitHub에서 설치 파일 배포

GitHub 저장소의 **Releases에 APK를 첨부**하면 태블릿 브라우저에서 내려받아 설치할 수 있습니다. 사용자에게 Git이나 Android Studio는 필요하지 않습니다. GitHub의 자동 생성 Source code ZIP은 설치 파일이 아닙니다. APK 파일을 선택해야 합니다.

공개 저장소는 [ssfssd/dex-tablet](https://github.com/ssfssd/dex-tablet)입니다. 다운로드 파일과 개발판 설명은 [v0.2.0 릴리스](https://github.com/ssfssd/dex-tablet/releases/tag/v0.2.0), 배포 정책은 [RELEASE.md](RELEASE.md)를 참고하세요. APK는 개발 서명이며, 같은 서명 키를 유지해야 이후 업데이트 설치가 가능합니다. 키와 기기 인증 정보는 공개 소스에 포함하지 않습니다.

## 코드 구성

- `MainActivity.java`: 실제 Android 진입 화면, USB 선택/허용, 입력 전달, 시스템 파일 선택기
- `DexSession.java`: 서버 준비, 화면 생성, 세션 정리 및 복원, 파일 전송
- `UsbTransport.java`, `MediaReceiver.java`: USB bulk I/O, H.264/PCM 재생
- `TabletCapabilities.java`, `core/DisplayProfile.java`: 수신 태블릿의 디코더와 표시 영역에 맞춘 화면 구성
- `core/`: Android에 의존하지 않는 ADB 인증/스트림/파일 프로토콜, scrcpy 메시지, 키보드, 좌표 변환 및 소유 화면 식별
- `tests/`: 합성 ADB 기기를 통한 검증. 실제 휴대폰/사용자 파일/기존 자격 증명을 사용하지 않음

Apache-2.0. scrcpy 4.1 서버 및 해당 라이선스/저작권 고지를 APK에 포함합니다. Samsung·Lenovo 공식 앱이 아닙니다.
